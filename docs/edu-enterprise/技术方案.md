# Label Studio 教育企业版 二次开发技术方案

> 版本：v1 草案 · 基于 Label Studio 主线最新提交（`595a0c9`）
> 目标读者：后端 / 前端 / 架构评审
> 状态：**待评审**

---

## 0. 需求与结论

| 需求 | 落地方案（一句话） |
|---|---|
| **任务分配** | 新增 `Assignment` 模型，接入 OSS 队列里已预留的 `assigned_flag` / "Manually assigned queue" 分支 |
| **权限管理** | 给成员加**角色**，覆写 `core/permissions.py` 的 `make_perm`，把「角色 → 权限点」用 `django-rules` 谓词绑定 |
| **多租户** | `机构 = Organization`（强隔离租户），`部门 = Workspace`（新增二级实体，学院/班级） |
| **师生映射** | 老师 = `manager`，学生 = `annotator`；支持**组织级 + 部门/项目级双层角色** |

**核心设计原则：不改内核，走扩展点。** Label Studio 开源版在代码里预留了大量给官方企业版（LSE）插桩的缝隙（mixin、`load_func`、`make_perm`、`assigned_flag`）。我们新建一个独立 Django app 顺着这些缝隙接入，内核只做最小侵入式改动，便于长期跟上游同步。

## 1. 现状分析（基于源码）

### 1.1 已有能力

- **组织**：`organizations/models.py` 中 `Organization` / `OrganizationMember`，`User.active_organization` 指向当前组织。`users` M2M `organizations` 通过 `OrganizationMember` 关联 —— **一人多组织天然支持**，切换靠 `active_organization`。
- **权限点**：`core/permissions.py` 的 `AllPermissions` 已列全（`projects.create`、`tasks.view`、`annotations.change` …）。
- **队列分配预留**：`projects/functions/next_task.py` 里 `get_not_solved_tasks_qs(..., assigned_flag)` 和 `get_next_task_without_dm_queue(...)` 已经有 `assigned_flag=True → "Manually assigned queue"` 分支。
- **项目成员**：`projects/models.py` 的 `ProjectMember(user, project, enabled)`。

### 1.2 缺口

| 缺口 | 说明 |
|---|---|
| 无角色区分 | `make_perm` 把**每个权限点都绑定成 `is_authenticated`** —— 组织内任何登录用户能做任何事 |
| 无部门层级 | 组织下没有「学院 / 班级」二级划分 |
| 无任务分配落库 | 队列有 `assigned_flag` 形参，但 OSS 没有产生它的数据源（分配表） |
| `ProjectMember` 无角色 | 只有 `enabled` 布尔，无法表达「A 老师是 X 项目的管理者」 |

### 1.3 关键扩展点（我们要接的缝）

```python
# core/settings/base.py
PROJECT_MIXIN            = 'projects.mixins.ProjectMixin'
ORGANIZATION_MIXIN       = 'organizations.mixins.OrganizationMixin'
USER_MIXIN               = 'users.mixins.UserMixin'
ORGANIZATION_MEMBER_MIXIN= 'organizations.mixins.OrganizationMemberMixin'
```

- `OrganizationMember.has_permission` / `UserMixin.has_permission`：权限判定中枢
- `core/permissions.py::make_perm`：权限谓词注册点，可覆写
- `projects/api.py:450`、`data_manager/actions/next_task.py:25`：`get_next_task()` 调用点，注入分配过滤

## 3. 数据模型设计

### 3.1 ER 概览

```
Organization (机构/学校) ──1:N── Workspace (部门/学院/班级) ──self FK── parent
     │                              │
     │ M2N (OrganizationMember)     │ M2N (WorkspaceMember, role)
     ▼                              ▼
   User ────────────────────────── User
     │
     │ 分配
     ▼
 Assignment (task, user, type, assigned_by, status)
     │
     ▼
   Task ──N:1── Project ──N:1── Workspace
```

### 3.2 表结构

**① OrganizationMember 扩展（内核表加字段，通过 migration）**

```python
# orgext 提供 mixin，字段通过 migration 加到 organization member 表
role = models.CharField(max_length=20, choices=Role.choices, default=Role.ANNOTATOR)
```
> 采用「加字段」而非新表，避免 join。字段落在 `organizations_organizationmember`。

**② Workspace（部门）— 新表**

```python
class Workspace(models.Model):
    organization = FK(Organization, related_name='workspaces')
    title        = CharField(max_length=1000)             # 计算机学院 / 2024级3班
    parent       = FK('self', null=True, related_name='children')  # 支持层级
    created_by   = FK(User, null=True)
    is_archived  = BooleanField(default=False)
    created_at / updated_at
```

**③ WorkspaceMember（部门成员 + 部门级角色）— 新表**

```python
class WorkspaceMember(models.Model):
    workspace = FK(Workspace, related_name='members')
    user      = FK(User, related_name='workspace_memberships')
    role      = CharField(choices=Role.choices, default=Role.ANNOTATOR)  # 部门级角色
    class Meta: unique_together = ('workspace', 'user')
```

**④ Project 扩展**

```python
workspace = FK(Workspace, null=True, blank=True, related_name='projects')  # 项目归属部门
```

**⑤ Assignment（任务分配）— 新表**

```python
class Assignment(models.Model):
    class Type(TextChoices):  ANNOTATOR='AN'; REVIEWER='RE'
    class Status(TextChoices): ASSIGNED='assigned'; IN_PROGRESS='in_progress'; COMPLETED='completed'
    task        = FK(Task, related_name='assignments')
    user        = FK(User, related_name='assignments')
    type        = CharField(choices=Type.choices, default=Type.ANNOTATOR)
    status      = CharField(choices=Status.choices, default=Status.ASSIGNED)
    assigned_by = FK(User, null=True, related_name='assignments_made')
    created_at / updated_at
    class Meta:
        unique_together = ('task', 'user', 'type')
        indexes = [Index(fields=['user', 'status']), Index(fields=['task'])]
```
> `ProjectMember` 保留不动（表示「谁能进这个项目」），`Assignment` 表示「具体哪条任务派给谁」，两层职责清晰。

## 4. 权限设计

### 4.1 角色定义（`orgext/roles.py`）

| 角色 | 常量 | 教育场景 | 典型权限 |
|---|---|---|---|
| Owner | `owner` | 机构负责人 | 全部，含删组织、计费 |
| Administrator | `admin` | 平台管理员/教务 | 建部门、管成员、跨部门 |
| Manager | `manager` | **老师** | 本部门内建项目、导数据、分配任务、审核、看统计 |
| Reviewer | `reviewer` | 助教/审核 | 审核标注、改标注、看统计（不建项目） |
| Annotator | `annotator` | **学生** | 只做分配给自己的任务、只标注 |

### 4.2 权限矩阵（节选，完整版在代码 `ROLE_PERMISSIONS`）

| 权限点 | owner | admin | manager | reviewer | annotator |
|---|:-:|:-:|:-:|:-:|:-:|
| `organizations.change` | ✅ | ✅ | — | — | — |
| `projects.create` | ✅ | ✅ | ✅ | — | — |
| `projects.view` | ✅ | ✅ | ✅ | ✅ | ✅* |
| `projects.change` | ✅ | ✅ | ✅ | — | — |
| `tasks.view` | ✅ | ✅ | ✅ | ✅ | ✅* |
| `annotations.create` | ✅ | ✅ | ✅ | ✅ | ✅ |
| `annotations.change`(他人) | ✅ | ✅ | ✅ | ✅ | — |
| `actions.perform`(分配) | ✅ | ✅ | ✅ | — | — |

> `*` = 仅限「分配给自己 / 自己所属部门」的对象（对象级过滤，见 §4.4）。

### 4.3 覆写 make_perm（角色谓词）

```python
# orgext/permissions.py
import rules
from orgext.roles import ROLE_PERMISSIONS  # {perm_name: {role, ...}}

def role_allows(perm_name):
    @rules.predicate
    def pred(user, obj=None):
        role = effective_role(user, obj)      # 组织级 or 部门/项目级取更高者
        return role in ROLE_PERMISSIONS.get(perm_name, set())
    return pred

def register_role_permissions():
    for perm_name in AllPermissions().model_fields... :   # 遍历所有权限点
        make_perm(perm_name, role_allows(perm_name), overwrite=True)
```
在 `orgext.apps.OrgextConfig.ready()` 里调用 `register_role_permissions()`，覆盖 OSS 默认的 `is_authenticated`。

### 4.4 双层角色的「有效角色」计算

```
effective_role(user, obj):
    base = OrganizationMember.role                     # 组织级
    if obj 有 workspace:
        wm = WorkspaceMember(user, obj.workspace).role # 部门级
        return max(base, wm)   # 取权限更高者
    return base
```
> 支撑「李老师在组织里是 annotator，但在『2024级3班』部门被提升为 manager」。对象级过滤（学生只看自己任务）在 `has_object_permission` + queryset 层双重保证。

## 5. 任务分配设计

### 5.1 分配动作

- Manager/Admin 在数据管理页选中一批任务 → 「分配给 X 同学」→ 批量创建 `Assignment`。
- 提供**自动分配**策略：按人数均分 / 按 overlap 派 N 人 / 轮询。放在 `orgext/queue.py::auto_distribute()`。

### 5.2 接入 OSS 队列（关键，改动极小）

OSS 已有形参，我们只需在调用点注入：

```python
# projects/api.py:450 & data_manager/actions/next_task.py:25 附近
from orgext.queue import filter_assigned

prepared_tasks, assigned_flag = filter_assigned(prepared_tasks, request.user, project)
next_task, queue_info = get_next_task(request.user, prepared_tasks, project, dm_queue,
                                      assigned_flag=assigned_flag)
```

```python
# orgext/queue.py
def filter_assigned(prepared_tasks, user, project):
    if project.workspace and project.distribution_mode == 'manual':   # 手动分配模式
        assigned_ids = Assignment.objects.filter(
            user=user, task__project=project, type='AN',
            status__in=['assigned','in_progress']).values('task_id')
        return prepared_tasks.filter(pk__in=assigned_ids), True
    return prepared_tasks, None   # 保持 OSS 抢单行为
```

> `assigned_flag=True` 时 OSS 会走 "Manually assigned queue"，并且**忽略 overlap / is_labeled**，正是我们要的「派给你就必须做」。

### 5.3 审核（Reviewer）

`Assignment.type=REVIEWER`：审核队列复用同机制，过滤 `type=RE` 且任务 `is_labeled=True`。审核结论写回 `Annotation`（OSS 已支持 review 相关字段，二期细化）。

## 6. 多租户 / 数据隔离

- **强隔离**：所有 queryset 已经/将要以 `organization = user.active_organization` 收口。`orgext` 补齐 Workspace 层过滤中间件：非本组织对象一律 404。
- **注册流程**：OSS 默认注册即建组织。改为：
  - 机构管理员注册 → 建 Organization（租户）。
  - 老师/学生通过**邀请链接/邀请码**加入指定 Workspace（复用 `Organization.token` + 新增 workspace token）。
- **切换**：顶栏组织切换器已存在（`active_organization`），增加部门筛选器（前端）。
- **跨部门统计**：Admin 可跨 Workspace 看汇总；Manager 仅本部门。

1. 新增表：`orgext_workspace` / `orgext_workspacemember` / `orgext_assignment`（纯新增，零风险）。

## 13. 存储方案（PostgreSQL + 云存储）

> 澄清：Label Studio 开源版**已支持** PostgreSQL 与云对象存储，本节是「配置 + 纳入权限体系」，不是从零开发。三层存储互相独立，别混淆。

### 13.1 三层存储

| 层 | 存什么 | OSS 默认 | 目标 | 开启方式 |
|---|---|---|---|---|
| **① 业务数据库** | 项目/任务/标注/用户/组织/本方案所有新表 | SQLite | **PostgreSQL** | 环境变量（见下），PG 是内置引擎 |
| **② 任务源/回写**（`io_storages`） | 待标注素材（图/文/音）、标注结果导出 | 本地文件 | S3 / GCS / Azure Blob / Redis | 项目内配 Cloud Storage，`io_storages` API |
| **③ 上传媒体**（`STORAGES`/MEDIA） | 直接上传文件、导出包、头像 | 本地 `media/` | S3 / Azure / GCS | `STORAGE_TYPE` 系列环境变量 |

### 13.2 ① 业务库切 PostgreSQL（生产必做）

`core/settings/base.py:163-189` 内置 `DATABASES_ALL`（postgresql/mysql/sqlite），default 已指向 postgresql。仅需环境变量，**无需改代码**：

```bash
DJANGO_DB=default
POSTGRE_NAME=labelstudio
POSTGRE_USER=ls
POSTGRE_PASSWORD=***
POSTGRE_HOST=postgres
POSTGRE_PORT=5432
```
官方 `docker-compose.yml` 即 app + PostgreSQL 组合，直接复用。我们所有新表（Workspace/Assignment…）的 migration 自然落到同一个 PG 库。

### 13.3 ② / ③ 云存储 + 部门隔离（这是我们要补的部分）

云存储本身开源版就能用，**教育版要补的是权限隔离**：

- **StorageConnection 归属 Workspace**：给 `io_storages` 的 Storage 记录关联 `workspace`（可空外键，复用 §3 思路），列表/使用按部门与角色过滤。
- **角色约束**：`storages.change` / `storages.sync` 仅 `manager+`（学生 `annotator` 不可配置存储）。已在 §4 权限矩阵体系内，加两行即可。
- **③ 媒体上云**（可选，多机部署时必需）：
  ```bash
  STORAGE_TYPE=s3            # 或 azure / gcs
  STORAGE_AWS_ACCESS_KEY_ID=...
  STORAGE_AWS_SECRET_ACCESS_KEY=...
  STORAGE_AWS_BUCKET_NAME=...
  STORAGE_AWS_REGION_NAME=...
  ```
  对应 `core/settings/base.py:755-799` 的 `CustomS3Boto3Storage` 等，切换后上传文件与导出包直接落云桶，多副本部署不再依赖本地磁盘。

### 13.4 落到实施计划

在 §10 计划中插入：
- **P0** 增加一项：`docker-compose` 起 PostgreSQL，业务库切 PG（本来就该做，先做掉）。
- **P2**（部门）中：Storage 关联 Workspace + 存储相关权限点纳入矩阵。
- ③ 媒体上云列为**部署项**（P5 加固/上线时按是否多机决定），非功能开发。
