# 多租户智能标注平台建设方案

> 面向对象：学校信息化主管 / 教务处 / 采购决策
> 底座：Label Studio 开源版 + 自研教育企业版扩展（`orgext`）
> 状态：**核心能力已开发并实测验证，前端管理页面待建设**

---

## 一、要解决的问题

学校要用标注平台支撑「AI 通识课 / 实训课」，但开源版 Label Studio 有三个天生的缺口：

| 缺口 | 具体表现 | 对学校的影响 |
|---|---|---|
| 无角色区分 | 组织内任何登录用户能做任何事 | 学生能建项目、删数据、改别人标注 |
| 无部门层级 | 组织下没有"学院/班级"二级划分 | 全校几千学生混在一个组织里，管不了 |
| 无任务分配 | 标注靠"抢单"，练不成"按学号布置作业" | 老师没法把指定任务派给指定学生 |

**结论**：不需要换平台，只需要在 Label Studio 上补一层"教育治理层"——多租户隔离、角色权限、任务分配。这正是我们已经完成开发并验证的部分。

---

## 二、方案总览

```
学校（机构 / Organization）
 ├── 学院 A（部门 / Workspace）
 │    ├── 2024级3班（部门 / Workspace，可嵌套）
 │    │    ├── 老师（Manager）
 │    │    └── 学生（Annotator）
 │    └── 标注项目（归属本部门，可开"手动分配"模式）
 │         └── 任务 → 分配 → 具体学生
 └── 学院 B（强隔离，互相看不到彼此数据）
```

- **机构 = 学校**：不同学校/不同批次天然强隔离，互不可见。
- **部门 = 学院/班级**：支持多级嵌套，一个学生可以属于多个班（如跨专业选修课）。
- **角色 = 老师/学生的自然映射**：老师管本部门，学生只做分配给自己的任务。
- **任务分配 = 数字化"发作业"**：老师选中一批数据、指定学生，学生登录后只看到自己的那份，做完算数、能追溯。

核心设计原则：**不改 Label Studio 内核，只走官方预留的扩展点**（mixin、权限注册钩子、队列过滤钩子）。好处是后续 Label Studio 官方版本升级时，我们的改动不会跟内核代码打架，冲突面可控。

## 三、角色与权限

| 角色 | 教育场景 | 能做什么 |
|---|---|---|
| **Owner** | 学校/机构负责人 | 全部权限，含删除机构、计费 |
| **Administrator** | 教务处/平台管理员 | 建学院/班级、管全校成员、跨部门查看 |
| **Manager** | **老师** | 本部门内建标注项目、导入数据、**分配任务给学生**、审核标注、看统计 |
| **Reviewer** | 助教/教辅 | 审核学生标注、改标注、看统计（不能建项目）——本期先占位，队列功能下一阶段接入 |
| **Annotator** | **学生** | 只能做分配给自己的任务，改不了别人的、建不了项目、进不了别的班 |

**双层生效**：一个人可以同时有"全校角色"和"班级角色"，取更高的那个。例如：一位助教在全校层面是学生权限，但在自己带教的班级里被单独设为老师权限——不需要在系统里开两个账号。

## 四、任务分配是怎么工作的

这是本方案对开源版改动最大、也是学校最关心的一块，**已经在真实环境里跑通验证**：

1. 老师建一个标注项目，勾选归属到具体班级，把"分配模式"从默认的"抢单"切换成"手动分配"。
2. 老师导入待标注数据后，选中一批任务，指定分配给哪几个学生（支持批量分配、也支持"按人数自动轮询均分"）。
3. 学生登录后点"下一条"，系统**只吐出分配给自己的任务**，不多不少，做完一条才有下一条（原生抢单逻辑里的"重叠度/去重"规则在这个模式下会被跳过，因为派给你的就必须由你做完）。
4. 老师随时能看到"谁分配了多少、完成了多少"，导出统计。

验证结果举例（真实跑出来的结果，不是设计假设）：

| 场景 | 结果 |
|---|---|
| 老师建项目、导入 4 条任务、分配 2 条给学生 A | 分配成功，记录可查 |
| 学生 A 领任务 | 只拿到分配给自己的那 2 条，队列标记为"手动分配队列" |
| 学生 A 想自己建一个标注项目 | 系统拒绝（403，无权限） |
| 学生 A 被老师临时提升为本班"小组长"（班级级角色提升） | 能改本班的项目，但改不了别的班、也建不了全新项目——权限边界精确到"这一个班" |

## 五、数据隔离与账号体系

- **强隔离**：不同学校/机构之间的数据在数据库层面完全隔离，跨机构查询直接返回"未找到"，不存在越权读取的可能。
- **加入方式**：不开放自助注册，老师/学生通过**邀请码/邀请链接**加入指定班级——避免野生账号混进系统。
- **批量导入**：支持教务提供的名单（CSV/Excel）批量建号、批量分班、批量设角色，不需要一个个手动录入。
- **跨班学生**：一个学生可以同时属于多个班（如辅修、选修课），系统原生支持，不需要开小号。

## 六、部署与存储建议

| 层 | 生产环境建议 | 说明 |
|---|---|---|
| 业务数据库 | PostgreSQL | Label Studio 内置支持，改环境变量即可切换，无需改代码 |
| 标注素材/导出结果 | 对象存储（S3/阿里云OSS/MinIO 等） | 支持多机部署，避免单机磁盘瓶颈 |
| 上传媒体/头像 | 对象存储 | 同上，多副本部署时是必需项 |

以上均为 Label Studio 开源版**已经支持**的能力，本方案只是把它们和权限体系打通（比如：存储配置这类操作，只有老师及以上角色能碰，学生看不到也改不了）。

## 九、给学校的建议

1. **可以先用起来**：核心的隔离、权限、分配能力已经就绪，教务/老师可以通过后台管理系统先用起来跑一个试点班级，验证流程是否符合教学习惯。
2. **界面是下一步的投入重点**：如果要给全校老师用，前端管理页面（尤其是"分配任务"这个高频操作）建议优先排期，这是目前唯一的体验缺口。
3. **按需上云**：试点阶段用默认配置即可；正式铺开到多个学院/多机部署时，再切 PostgreSQL + 对象存储，改动是配置级别的，不影响已有数据。
